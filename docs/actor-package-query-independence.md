# Independent package and inventory reads

An explicit NPC EVP request uses the existing source package selector and queues
its selected result for the ordinary native procedure phase. A stopped attached
reference-script invocation does not own that separate selection operation.
Its exact error and consumed locals stay retained. A failed PACK event lifecycle
still refuses EVP; selection never clears or replays that source result.

NPC and creature package GetItemCount conditions resolve their actual self,
declared target or explicit reference through the shared condition subject
owner. A current player count uses the authoritative player inventory, not the
NPC's source outfit list. Declaring-master item/reference identities and absent
item zero remain distinct from an absent inventory adapter, invalid counts or
unowned target contexts.

Runtime admission binds the existing inventory command owner before initial
package selection. Count changes remain live and the helper creates no
replacement inventory or source condition value. Other package predicates,
procedures, target election and sensory behavior keep their existing boundaries.

Pure subject/count contracts and an unchanged owned package-evaluation component
pass current and cold selected-result checks, source error/prefix retention and
actual package-event refusal. This does not establish the original interrogation
conversation, whole actor behavior, ordinary saving or matched retail timing.
