# Whole-stack quest and script coverage

The development lab's `quest-graph` command reads the complete winning source
stack in place. Discovery examines every winning record payload, including
deleted winners and signatures with embedded patrol, perk, recipe and result
programs. Empty headers, empty or repeated bodies, compiled-only programs,
orphan fields and disabled references remain in the denominator. An unread
record makes the remaining original program denominator unknown.

Every SCHR, SCDA, SCTX, SCRO, SCRV, SLSD, SCVR and SCED retains its original
record identity, field ordinal, byte length and hash. Raw field identities and
counts must equal the independently grouped rows. Known delimiters associate
static extents; this accounting does not admit a canonical execution scope for
an orphan or future layout. Every SCTX body has its own parser disposition,
including empty and repeated declarations; a single representative cannot
stand in for its siblings. The summary reports compiled execution ownership as
unknown rather than inferring zero owners from a static inspection.

Each program retains its source/master identity, compiled-body hash, declared
byte/reference extents, source-parser outcome and direct statement-name inventory. Form
references resolve through the declaring plugin; local-reference extents are
counted separately from variable semantics. Every quest retains authored stages,
objectives, result-entry count and attached script. SetStage edges are recorded
across every parsed source arm; an absent authored stage is a separate fact from
whether the engine admits that transition.

Every CTDA is decoded independently of runtime eligibility. Every successfully
parsed statement is inspected in original event/block order. `if`, `elseif` and
`while` retain both predicate outcomes even when the current save would skip an
arm. The shared deferred expression parser checks complete syntax and actual
function signatures without invoking functions, assignments, state reads,
random draws, lifecycle queries or user-function bodies. Undeclared operands,
missing caller context and unsupported expressions remain per-statement errors.
Legacy statement dispatch is explicitly uninspected rather than called with
invented arguments. Inspection never admits a placed reference to the world.

Direct statement names are distinct names per source-body owner, not every call
occurrence. They exclude expression functions and legacy statement-argument
calls. The deferred parser retains no complete call AST and stops at refused
syntax or names, so successful signature lookup cannot certify that denominator.
Both call counts remain null while any SCTX exists or a source layout is unread;
only complete readable source absence establishes zero diagnostic source calls.
Compiled instruction coverage remains independently unknown. Authored inactive,
nested, loop, assignment, malformed and legacy-argument cases retain this boundary
without invoking functions or reading/writing gameplay state.

Source event blocks accept bare End or one optional case-insensitive name that
matches the open event. A label does not select another event or reproduce its
filter/parameters. Orphan, repeated, mismatched, quoted, numeric and extra-token
closers, open branches/loops and missing closers retain failures. Actual
Debug/Release full-reader contracts retain the original fields, inactive arms
and uninspected compiled bodies without invoking any event. Independently read
original matching-label fields now parse in FNV, TTW and combined with unchanged
source and complete raw-field report hashes; unrelated failures remain intact.
Parser version, saved program identity and missing-owner migration permission
remain unchanged. Complete corpus reads under this newer parser remain pending.

The finite denominator is authored predicates and alternatives. Its independent
Boolean domain is represented symbolically as 2^N; correlated or unreachable
valuations are not asserted as playable states. Numeric state, loop iteration,
recursion, native plugin hooks, timing and presentation require their own owners
and measurements. Source parsing is not authoritative SCDA execution. A valid
compiled-only body remains visible even when source interpretation cannot run it.

The synthetic contract inspects inactive arms, a loop, an unknown command and
malformed inactive syntax. Instrumented callbacks prove zero function invocation,
value reads and writes. Ordinary short-circuit execution also retains its deferred
source-string ownership. The owned audit pins the complete selected source stack
and separately reports record/program/condition accounting, structural failures,
expression declarations and the untouched world-instance count. These checks
do not establish campaign, whole-level or matched-retail parity completion.

The source audit exits with failure while a parser/extent failure or unmeasured
script/condition behavior remains. Its source field accounting can pass while
runtime readiness fails. Complete source-row counts therefore cannot become a
whole-game readiness result. Synthetic contracts include deleted winners,
orphan/empty/repeated fields, compiled-only bodies and a malformed compressed
record. A genuine framed compressed empty record remains valid; a missing or
unsupported compressed envelope refuses before decompression can return empty.
Explicit inflater reads and a completion-aware input refuse EOF before the
final block; the framework's optimized CopyTo cannot establish this boundary.
The authored non-final empty block is refused and genuine empty and existing
bad-checksum compatibility remain valid. A shared first-party structural owner
independently validates stored/fixed/dynamic blocks, repeated code lengths,
history/window bounds, output count and exact final occupied bytes before both
record inflation paths. Buffered input position alone is not that proof. Actual
reader contracts retain legal padding and overlapping/cross-block history while
refusing truncation, trailing bytes and concatenated members. Archive contracts
use the same structure owner while preserving strict checksum behavior.
