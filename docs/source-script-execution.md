# Source script execution

The production opening now executes its recurring GameMode source through the
shared quest-script owner. It no longer selects timed destinations by extracting
SetStage from the text and discarding intervening calculations. The existing
stage/menu presentation adapter still owns immediate stage results and modal
handoffs; this is not full script-engine or opening parity.

SCRO references bind names to master-adjusted winning forms. SLSD/SCVR bind
local and qualified quest variables to winning declaration slots. A matching
editor ID elsewhere in the load order is insufficient. Stage variable SETs
validate their compiled result-script scope and publish alongside existing
stage-global writes. Global storage remains Float32; current quest-variable
storage remains double. Telemetry exposes variable slots, values and exact bits.

Expressions retain arithmetic precedence, nested conditions, short circuits and
source function arguments. The current host binds GetStage, GetSecondsPassed,
Abs, GetObjectiveDisplayed and the player's owned SPECIAL values. Reached
unknown commands, functions and references fail closed. Invocation writes are
prepared before publication, followed by the validated SetStage effect. Effects
after SetStage require synchronous result-script execution and remain rejected.

Synthetic probes cover changed variable indices in a winning script override,
source-order assignments, nested function expressions, inactive calls, source
stage progression, cold recurrence and failure without partial variable writes.
Thirty owned SPECIAL/sex cases execute the complete reaction program and select
eligible INFOs. All six balanced-case calculated values agree with retained
native telemetry. These are component results; other branches have not all
received independent native execution comparisons.

Ordinary room-74 accepts original creation and Vigor, plays the source reaction
and the following three responses, then reaches stage 80. The next package-event
failure remains visible. SCTX decoding now accepts its declared byte extent
with or without a terminal null while rejecting embedded nulls. Actual package
event commands still need lifecycle execution; decoding them is not execution.
The selected nine-package check admits eight and retains one nonempty POEA
event as unbound. The full C#/Godot gate passes with these boundaries visible.

Remaining owners include exact claimed-script lifetime and MenuMode scheduling,
mutable delays, quest start/stop, conditional/multiple stage results, combined
global/local expressions, reference-instance variables, complete actor values,
activation scripts and package events. The existing character menu handoff
delivers its source MenuMode block at close, which does not establish native
event timing. No native observation supplies gameplay state. The replacement
psychology panel and its stage skip have been removed; original interaction and
dialogue must supply the next progress.
